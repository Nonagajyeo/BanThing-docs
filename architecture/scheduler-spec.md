---

## 1. 개요

본 문서는 '반띵' 서비스의 모임(Meeting) 상태를 자동으로 변경하는 백그라운드 스케줄러의 기능과 동작 방식을 정의합니다. 이 스케줄러는 사용자의 직접적인 요청 없이, 정해진 시간에 따라 모임의 생명주기(Life Cycle)를 관리하여 서비스의 신뢰성과 데이터 정합성을 보장합니다.

---

## 2. 주요 기능

`MeetingSchedulerService`는 두 가지 핵심 기능을 수행합니다.

1.  **모임 자동 시작**: 모집 중인 모임이 약속된 시작 시간이 되면 '진행중' 상태로 변경합니다.
2.  **모임 자동 완료**: 진행 중인 모임이 일정 시간(24시간)이 지나면 '모임종료' 상태로 변경합니다.

---

## 3. 스케줄러 상세 명세

### 3.1. 모임 자동 시작 (`startScheduledMeetings`)

- **목적**: 사용자가 직접 상태를 변경하지 않아도, 약속된 시간에 모임이 자동으로 시작되도록 처리합니다.
- **실행 주기**: **매 분 0초마다** (`cron = "0 * * * * *"`)
- **대상**:
    - 현재 상태가 `RECRUITING`(모집중) 또는 `FULL`(모집마감)인 모든 모임
    - 모임 시작 시간(`meetingDate`)이 현재 시간보다 과거인 모임

- **주요 로직**:
    1.  1분마다 실행되어 시작 시간이 지난 `RECRUITING` 또는 `FULL` 상태의 모임을 모두 조회합니다.
    2.  조회된 모임들을 순회하며 다음 조건을 확인합니다.
        - **(예외 처리)** 만약 모임이 `RECRUITING` 상태이고, 참여자가 1명(호스트)뿐이라면 모임을 시작하지 않고 `CANCELLED`(모임취소) 상태로 변경합니다. 이는 참여자가 없어 불필요하게 진행되는 모임을 방지하기 위함입니다.
        - 그 외의 경우에는 모임 상태를 `ONGOING`(진행중)으로 변경합니다.
    3.  상태 변경이 일어날 때마다 로그를 기록하여 서버 동작을 추적할 수 있도록 합니다.

### 3.2. 모임 자동 완료 (`autoCompleteMeetings`)

- **목적**: 오랜 시간 동안 '진행중' 상태로 남아있는 모임들을 자동으로 '모임종료' 처리하여 데이터의 정합성을 유지합니다.
- **실행 주기**: **매일 자정** (`cron = "0 0 0 * * *"`)
- **대상**:
    - 현재 상태가 `ONGOING`(진행중)인 모든 모임
    - 모임 시작 시간(`meetingDate`)으로부터 **24시간이 경과**한 모임

- **주요 로직**:
    1.  매일 자정에 실행되어, 시작된 지 24시간이 지난 `ONGOING` 상태의 모임을 모두 조회합니다.
    2.  조회된 모임들의 상태를 `COMPLETED`(모임종료)로 변경합니다.
    3.  각 모임의 처리 결과를 로그로 남깁니다.

---

## 4. 기술적 참고사항

- **활성화 설정**: `SchedulingConfig.java` 파일의 `@EnableScheduling` 어노테이션을 통해 프로젝트 전체의 스케줄링 기능이 활성화되어 있습니다.
- **트랜잭션 관리**: 모든 스케줄러 메서드는 `@Transactional`로 관리되어, 상태 변경 작업 중 오류가 발생할 경우 모든 변경사항이 롤백(Rollback)됩니다.
- **Cron 표현식**: 스케줄러의 실행 주기는 `@Scheduled` 어노테이션의 `cron` 속성을 통해 제어됩니다.
    - `0 * * * * *`: 매 분 0초
    - `0 0 0 * * *`: 매일 0시 0분
