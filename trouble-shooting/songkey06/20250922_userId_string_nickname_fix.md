## 🧩 문제 상황
- 특정 API 응답 객체에 `userId`가 포함되어야 했는데, 실제로는 `userId: userNickName` 형태로 잘못 들어가는 문제 발생
- 결과적으로 사용자 식별이 올바르게 되지 않아 이후 로직에서 에러 발생 가능성 존재

---

## 🔍 원인 분석
- 처음에는 직렬화/역직렬화 과정에서의 매핑 문제로 추정
- 디버깅 결과, API에서 내려주는 객체에 `userId` 필드가 존재하지 않고 대신 `userNickName`이 들어와 있음을 확인
- 즉, 타입 매핑 시 `userId` → `String`으로 잘못 들어와 닉네임이 바인딩됨

---

## 🛠 해결 방법
1. 수신 객체에서 `userId` 필드 타입을 `String`으로 설정
2. 값이 닉네임인지 ID인지 판별하는 로직 추가
    - **닉네임인 경우**: DB 조회를 통해 해당 닉네임의 `userId`를 찾아옴
    - **ID인 경우**: 그대로 사용
3. 매핑 로직 개선 후 재빌드 및 배포 진행

---

## ✅ 결과
- 이후 API 응답에서 닉네임이 들어와도 내부적으로 올바른 `userId`로 매핑됨
- Postman 테스트 및 실제 서비스 호출에서 정상 동작 확인

---

## 📚 교훈 / 예방책
- API 설계 시 **식별자와 표시자(닉네임, 이름 등)를 혼동하지 않도록 명확히 구분** 필요
- DTO/Entity 매핑 시 타입과 필드명을 엄격히 검증할 수 있는 단위 테스트 추가
- Swagger 문서 등 API 스펙을 클라이언트/서버 간 반드시 공유하고 확인할 것
