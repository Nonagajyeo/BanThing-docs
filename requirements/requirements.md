# 반띵 – 대형마트 소분 모임 서비스 요구사항 명세서

---

- **버전**: v1.0.3

- **작성자**: 강관주

### 1. 개요 (Overview)

BanThing은 **지도 기반의 대용량 상품 소분 커뮤니티 플랫폼**입니다. 1~2인 가구의 합리적인 소비를 돕고, 지역 커뮤니티를 활성화하는 것을 목표로 합니다. 기존에 파편화되어 있던 소분 모임을 한곳으로 통합하여 탐색의 불편함을 해소하고, 투명한 거래 환경을 제공하는 데 중점을 둡니다.

---

### 2. 목적 (Purpose)

* 지도 기반의 직관적인 탐색 환경을 제공하여 사용자들이 근처의 소분 모임을 쉽게 찾고 참여할 수 있도록 합니다.
* 호스트의 모임 개설 및 신청자 관리 기능을 지원하여 체계적인 모임 운영을 돕습니다.
* 댓글 시스템을 통해 모임 전후의 소통을 지원하고, 피드백 시스템으로 신뢰를 쌓을 수 있는 커뮤니티를 구축합니다.

---

### 3. 핵심 기능 (Core Features)

* **소셜 로그인**: 카카오톡 로그인을 통해 간편하게 회원가입 및 로그인을 지원
* **지도 기반 모임 탐색**: 지도 API를 활용해 마트 지점별 소분 모임 정보를 직관적으로 확인
* **AI 챗봇 검색**: 자연어 질의를 통해 원하는 조건의 모임을 대화 형태로 검색 (필요 준비물 등 확장 예정)
* **댓글 소통**: MVP 단계에서는 모임 참여 신청부터 세부 조율까지 모든 소통을 댓글로 진행
* **사용자 신뢰도 점수 시스템**: 모임이 종료된 후 피드백을 기반으로 점수를 부여받아 신뢰도를 관리

### 4. 기능 요구사항 (Functional Requirements)

#### 4.1 회원/인증

| ID    | 기능 상세                | 우선순위   | 비고                    |
|-------|----------------------|--------|-----------------------|
| FR-01 | 카카오톡 소셜 로그인을 통한 회원가입 | MUST   | 비밀번호 미저장              |
| FR-02 | JWT 기반 로그인 및 로그아웃    | MUST   | 토큰을 쿠키에 저장            |
| FR-03 | 최초 로그인 시 약관 동의       | MUST   | '동의' 혹은 '로그아웃' 버튼 제공  |
| FR-04 | 마이페이지                | MUST   | 프로필, 신뢰도 점수, 모임 목록 조회 |
| FR-05 | 마이페이지: 프로필 수정        | SHOULD | 사진, 닉네임, 자기소개 등       |
| FR-06 | 마이페이지: 회원 탈퇴         | SHOULD | 논리적 삭제 적용             |
| FR-07 | 부적절한 사용자 신고          | SHOULD | 관리자에게 메시지 전송          |


* **회원가입**: 카카오톡 소셜 로그인을 통해 회원가입을 진행, 비밀번호 미저장
* **로그인/로그아웃**: JWT 기반 인증, 토큰을 쿠키에 저장하여 전역 상태 관리
* **마이페이지**: 프로필 수정(사진, 닉네임, 자기소개 등)과 내가 참여한/승인 대기중인 모임 목록(페이지네이션), 신뢰도 점수 및 등급 조회 지원

#### 4.2 모임 관리(호스트)

| ID    | 기능 상세          | 우선순위   | 비고                             |
|-------|----------------|--------|--------------------------------|
| FR-08 | 모임 개설          | MUST   | 제목, 장소 카테고리, 시간, 소개, 썸네일 이미지 등 |
| FR-09 | 모임 수정          | SHOULD | PUT 방식                         |
| FR-10 | 모임 삭제          | MUST   | DELETE 방식                      |
| FR-11 | 모집 마감          | SHOULD | PUT 방식                         |
| FR-12 | 모임 자동 진행 혹은 취소 | MUST   | 스케줄러에 의해 실행                    |
| FR-13 | 모임 종료          | MUST   | POST 방식                        |
| FR-14 | 모임 자동 종료       | MUST   | 스케줄러에 의해 실행                    |
| FR-15 | 신청자 관리         | MUST   | 신청 목록 확인                       |
| FR-16 | 신청자 관리         | MUST   | POST 방식                        |
| FR-17 | 참가자 제거         | SHOULD | DELETE 방식                      |

* **5가지 모임 상태**:
  * **모집중(`RECRUITING`)**
  * **모집마감(`FULL`)**
  * **진행중(`ONGOING`)**
  * **종료(`COMPLETED`)**
  * **취소(`CANCELLED`)** 

* **모임 개설**: 제목, 장소 카테고리, 시간, 소개, 썸네일 이미지(선택),
  최대 인원은 5명으로 고정, 초기 모임 상태는 모집중(`RECRUITING`)

* **모임 수정**: `PUT` 방식을 사용하여 전체 정보를 업데이트

* **모임 삭제**: `DELETE` 방식을 사용하여 모임을 논리적으로 삭제(deleted_at 컬럼을 업데이트)

* **모집 마감**: `PUT` 방식을 사용하여 모임의 상태를 모집마감(`FULL`)으로 변경

* **모임 자동 진행 혹은 취소**: 스케줄러에 의해 매 분마다 `모집 중`이거나 `모집 마감` 상태이고,
  시작 시간이 지난 모임을 진행 중(`ONGOING`) 상태로 변경<br>
  그리고 참여자가 호스트 1명 뿐인 모임은 자동으로 모임 취소(`CANCELED`) 상태로 업데이트

* **모임 종료**: POST 방식을 사용하여 진행중(`ONGOING`) 상태인 모임을 종료(`COMPLETED`) 상태로 변경

* **모임 자동 종료**: 스케줄러에 의해 매일 자정에 실행되며, 진행중(`ONGOING`)인 모임들 중
  시작된 지 24시간이 지난 모임들을 자동으로 완료(`COMPLETED`) 상태로 변경

* **신청자 관리**: 신청 목록 확인 및 `POST` 방식으로 승인(`APPROVE`) 또는 거절(`REJECT`) 처리

* **참가자 제거**: `DELETE` 방식을 사용하여 참가자를 논리적으로 삭제(내보내기)


#### 4.3 모임 탐색/신청(참여자)

| ID    | 기능 상세       | 우선순위   | 비고                          |
|-------|-------------|--------|-----------------------------|
| FR-18 | 모임 목록 조회    | MUST   | 카드형 레이아웃 및 페이지네이션           |
| FR-19 | 모임 필터/검색    | MUST   | 지도 선택, 검색(매장, 제목, 소개)       |
| FR-20 | AI 챗봇 검색    | MUST   | 자연어 질의를 통한 모임 검색 기능         |
| FR-21 | 모임 상세 조회    | MUST   | 로그인 회원만 상세 내용 확인 가능         |
| FR-22 | 모임 참여 신청    | MUST   | POST 방식                     |
| FR-23 | 모임 참여 신청 취소 | SHOULD | DELETE 방식                   |
| FR-24 | 신청 상태 확인    | SHOULD | PENDING, APPROVED, REJECTED |

* **모임 목록 조회**: 카드형 레이아웃 형태이며 한 페이지에 최대 5개 페이지네이션, 비회원도 확인 가능
* **모임 필터/검색**: 지도에 설정되어있는 핀을 클릭 혹은
  검색창에 타이핑한 문자열을 기준으로 존재하는 모임의 매장 이름, 제목, 소개와 동일한 항목을 필터링 

* **AI 챗봇 검색**: 사용자가 자연어로 질문하면, 챗봇이 그 문장에서 키워드를 추출하여 모임 목록을 찾아주고 대화 형태로 결과를 보여줍니다.
  
* **참여 신청**: 모임이 모집 마감(`FULL`), 진행(`ONGOING`) 상태가 되기 전 신청 가능

* **참여 신청 취소**: `DELETE` 방식을 사용하여 참여 신청 내역을 논리적으로 삭제

* **신청 상태**: PENDING(승인대기) → APPROVED(승인) / REJECTED(거절)


#### 4.4 모임 게시판

| ID    | 기능 상세 | 우선순위   | 비고                                  |
|-------|-------|--------|-------------------------------------|
| FR-25 | 댓글 읽기 | MUST   | 비참여자는 읽기 전용, 호스트/승인된 참여자는 쓰기, 수정 가능 |
| FR-26 | 댓글 작성 | MUST   |                                     |
| FR-27 | 댓글 수정 | MUST   |                                     |
| FR-28 | 댓글 삭제 | SHOULD |                                     |

* **개념**: 소분 품목과 일정 등 모임에 대한 질문을 공유하는 공간으로 활용
* **접근 권한**: **호스트 또는 승인된 참여자**만 댓글 작성 가능, 비참여자는 읽기 전용
* **댓글**: 작성/수정/삭제

#### 4.5 피드백(신뢰도 점수)

| ID    | 기능 상세                      | 우선순위 | 비고                                    |
|-------|----------------------------|------|---------------------------------------|
| FR-29 | 피드백 작성                     | MUST | 모임 상태 `COMPLETED`, 본인 제외              |
| FR-30 | 사용자 신뢰도 점수 시스템             | MUST | 초기 점수 300점                            |
| FR-31 | 신뢰도 등급 확인                  | MUST | 500점 이상: 좋음, 100~499점: 기본, 99점 이하: 경고 |

* **개념**: 모임이 종료된 후 참여자에게 점수를 부여하여 신뢰도 등급을 관리하는 시스템
* **조건**: 모임이 **종료(`COMPLETED`)** 상태이고, 본인을 제외한 대상에게만 가능
* **작성/조회**: 모임이 종료된 후 모임 상세 페이지에서 점수 부여 가능, 마이페이지에서 자신의 신뢰도 점수 및 등급에 따른 뱃지 확인 가능
* **사용자 신뢰도 점수 시스템**:
  * **점수 획득**:
    * 모임 생성: +2점
    * 모임 참여: +1점
    * 좋은 피드백 1개당: +5점
  * **점수 차감**:
    * 노쇼: -20점
    * 나쁜 피드백 1개당: -5점
  * **현재 단계 구현**: 피드백만 구현되었고, 생성, 참여, 노쇼 점수는 미반영
* **신뢰도 등급**:
  * 좋음 (500점 이상)
  * 기본 (100점 ~ 499점)
  * 경고 (99점 이하)
  * 등급에 따라 닉네임 앞 배지 추가

### 5. 비기능 요구사항 (Non-functional Requirements)

* **성능**: 평균 응답 1.5초 이내
* **보안**:
  * JWT 토큰 기반 인증, 토큰을 쿠키에 저장
  * API 권한 검증을 통해 `401`(인증 실패) 및 `403`(권한 없음) 에러를 처리
  * 민감정보 마스킹/로그 금지
  * 카카오 소셜 로그인 구현 방식
    * `OAuth 2.0`의 `Authorization Code Grant`를 사용
    * **인가 코드 발급**: 사용자가 '카카오 로그인' 버튼을 클릭하면, 백엔드 서버가 사용자를 카카오 로그인 페이지로 리다이렉트합니다.
    * **토큰 교환**: 카카오 로그인 완료 후, 카카오 서버는 인가 코드를 백엔드 서버로 직접 전달합니다. 백엔드는 이 인가 코드로 카카오에 토큰을 요청하여 교환합니다.
    * **장점**: 모든 토큰 교환 과정을 백엔드에서 처리하여 보안성이 높습니다.
* **신뢰성/정합성**: 정원 초과/중복 신청 방지를 트랜잭션으로 보장, 삭제 시 논리적 삭제 적용
* **사용성**: 앱 UI 형태로 제작하여 사용 편의성 증대
* **운영**: 회원가입/모임 생성/에러 로깅, 감사 추적(누가 언제 무엇을)

### **6. 운영 정책**

* **회원 관리**

  * 만 14세 이상만 가입 가능
  * 휴면 계정은 12개월 동안 로그인하지 않으면 자동 탈퇴 처리
  * 논리적 삭제된 회원 데이터는 6개월간 보관 후 완전 삭제

* **모임 운영**

  * 모임 최대 인원은 5명으로 고정
  * 모집 마감 이후에는 새로운 신청 불가
  * 호스트는 임의로 참가자를 제거할 수 있으나, 기록은 감사 추적용으로 보관
  * 모임은 시작 시간이 지나면 자동으로 상태가 갱신됨 (ONGOING/취소)

* **신뢰도 정책**

  * 신뢰도 점수 99점 이하인 사용자는 모임 개설 불가
  * 노쇼가 2회 이상 누적될 경우, 1개월간 모임 참여 정지
  * 신고가 3회 이상 누적된 계정은 관리자가 검토 후 활동 제한 가능

* **데이터 보관 및 삭제**

  * 모임 및 댓글은 논리적 삭제 적용 (deleted\_at 컬럼 업데이트)
  * 논리적으로 삭제된 데이터는 6개월 보관 후 완전 삭제

### **7. 제약 사항**

* **기술적 제약**

  * MVP 단계에서는 실시간 채팅, 결제 기능 미지원
  * 지도 기능은 Kakao Map API만 사용
  * 서버 평균 응답 속도는 1.5초 이내를 목표로 함
  * 백엔드는 Spring Boot, 프론트는 React로 구현

* **비즈니스 제약**

  * 오프라인 만남 기반 소분 모임만 지원 (배송 서비스 제외)
  * 모임 정원은 5명 이상 불가
  * 결제·정산은 서비스 외부에서 사용자 간 직접 진행 (Phase 3에서 개선 예정)

* **보안 및 운영 제약**

  * 모든 회원 인증은 카카오 소셜 로그인(OAuth 2.0) 기반
  * 민감 정보(비밀번호, 주민번호 등) 저장 금지

* **내부 개발 한계**

  * 서버 구성은 **백엔드(Spring Boot) 1대 + 프론트엔드(React) 1대**로 제한
  * 멀티 리전, 멀티 서버 환경 미지원 (확장성 제한)
  * DB는 단일 인스턴스로 운영 (샤딩, 리플리케이션 미적용)
  * CI/CD 자동화는 최소 수준(GitHub Actions 통한 단순 배포), 고도화된 배포 전략 미지원
  * 모니터링/로깅은 기본 수준만 적용 (고급 분석, 알림 시스템 미지원)

### **9. 용어 정의 (Glossary)**

* **모임(Meeting)**: 오프라인 소분 이벤트의 단위
* **호스트(Host)**: 모임 개설·운영 권한자
* **참여자(Participant)**: 모임에 신청/승인되어 활동하는 사용자
* **피드백(Feedback)**: 사용자의 활동과 상호 평가에 기반한 신뢰도 점수 시스템
* **신뢰도 점수(Trust Score)**: 사용자의 활동(모임 생성/참여) 및 피드백에 따라 부여되는 점수
* **모임 게시판(Comment)**: 해당 모임 참여자 전용 소통 공간
